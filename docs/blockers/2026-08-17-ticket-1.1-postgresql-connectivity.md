# Blocker Resolution: Ticket 1.1 PostgreSQL Connectivity

## Related ticket and milestone

- Ticket: `1.1 Implement inventory persistence`
- Milestone: `M1 — Manual inventory and shared batch workflow`

## Dates

- Encountered: 2026-08-17
- Resolved: 2026-08-17

## Context

Ticket 1.1 required repository-controlled PostgreSQL access for migration verification and persistence tests using the documented host-based development model.

## Symptoms

- `npm run db:wait` initially succeeded in some runs but later verification produced `ECONNREFUSED 127.0.0.1:15432`.
- Subsequent verification attempts produced `Connection terminated unexpectedly` and `ECONNRESET` during migration or persistence tests.
- At different points, the PostgreSQL container was observed as unavailable, `exited`, or `unhealthy`.

## Impact on the ticket

- Migration verification could not be completed reliably.
- Persistence tests could not be treated as authoritative evidence.
- Commit, push, checklist synchronization, and ticket advancement were blocked until the database path was re-verified.

## Hypotheses considered

- Repository-controlled Compose or environment configuration mismatch
- Mismatch between published host port and `DATABASE_URL`
- PostgreSQL container instability or unhealthy state
- Execution-environment limitation rather than a repository defect

## Diagnostic steps and evidence

- Inspected resolved Compose configuration and confirmed published host port `15432:5432`.
- Verified `.env` and runtime configuration both targeted `postgres://pantry:pantry@127.0.0.1:15432/pantry`.
- Inspected container state, health, and PostgreSQL logs.
- Verified that a direct host-side query and a Compose-internal query could succeed once the container stabilized.
- Re-ran `npm run migrate` and persistence tests after explicitly starting the repository-controlled container and verifying readiness.

## Confirmed root cause

The diagnostic evidence did not demonstrate a persistent repository wiring defect. The failure was consistent with transient repository-controlled PostgreSQL availability and execution-environment instability during early verification runs. Once the container was explicitly started and allowed to stabilize, host-based connectivity, migration execution, and persistence testing succeeded.

## Resolution

- Explicitly started the repository-controlled PostgreSQL container.
- Verified readiness before migration and persistence verification.
- Re-ran migration and persistence tests after the database path stabilized.
- Tightened invalid-value validation and added targeted persistence tests once the database path was reliable.

## Verification proving resolution

- `npm run db:wait` succeeded.
- `npm run migrate` executed successfully.
- Re-running `npm run migrate` safely skipped already applied migrations.
- `npm test` passed with all inventory persistence tests succeeding.
- Host-based database query and Compose-internal query both succeeded during the final diagnostic pass.

## Recurrence indicators and recovery guidance

- If `ECONNREFUSED 127.0.0.1:15432`, `Connection terminated unexpectedly`, or `ECONNRESET` recur during database verification, inspect the PostgreSQL container state and health before changing application code.
- Reconfirm the repository-controlled Compose service is running and healthy before rerunning migrations or persistence tests.
